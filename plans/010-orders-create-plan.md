# Plan 010: Orders, create an order

- Number: 010
- Created: 2026-11-04
- Spec: [.specs/010-orders-create.md](../.specs/010-orders-create.md)

## Concept summary

No open question; the spec lists the contract, every validation rule, and the pricing example. Choices made in this plan, each recorded in `adrs/orders-create.md`:

1. **Domain.** `Order.place(...)` is the totals rule: each line total is `unitPrice * quantity`, the subtotal is the sum of the lines, the fee is `DeliveryPolicy.DELIVERY_FEE_IN_CENTS`, the total is subtotal plus fee. `OrderItem`, `Address`, and `OrderStatus` (only `CONFIRMED`) are records and an enum with no Spring and no JSON.
2. **Application.** `CreateOrderUseCase.execute(CreateOrderCommand)` asks the port `CoffeePriceLookup` for the coffees (the `orders` slice never imports `catalog`), answers `422 unprocessable_content` with `fields.items` when an id is not in the catalog, builds the order from the **catalog** names and prices, and saves it through `OrderRepository`. The client sends no price the server would use: a `priceInCents`, `unitPriceInCents`, or `totalInCents` anywhere in the body is an unknown property and is ignored.
3. **Infrastructure.** `JdbcCoffeePriceLookup` reads `coffees` directly (its own SQL, the shared database). `JdbcOrderRepository.save` is `@Transactional`: the order row and every line are stored together or not at all.
4. **Validation lives in `interfaces`**, as request-shape work, in a plain `CreateOrderRequestValidator` that collects **all** problems and throws `ValidationFailedException` with `fields` keyed by JSON path (`items`, `items[0].quantity`, `address.zipCode`, `paymentMethod`). No Bean Validation dependency: the messages, the paths, and trimming are all custom, and the validator is a unit-tested class. Text fields are trimmed; a blank `complement` becomes `null`.
5. **Strict types.** `quantity` is read as a JSON node and must be an integral number (a string such as `"2"` or a decimal such as `1.5` is rejected). A value Jackson cannot convert (for example an object where a string is expected) becomes `400 validation_failed` with the JSON path of the bad value instead of the generic `body` key.
6. **Shared errors.** `shared.error` gets `UnprocessableContentException` (`422 unprocessable_content`, with `fields`) and `NotFoundException` (`404 not_found`, used by spec 011), both mapped by `ApiExceptionHandler`, and the code `UNPROCESSABLE_CONTENT`.
7. **Response.** `OrderResponse` (package-private record, shared with spec 011) has `id`, `status`, `items`, `address`, `paymentMethod`, `subtotalInCents`, `deliveryFeeInCents`, `totalInCents`, `currency`, `estimatedDeliveryMinutes`, `createdAt`. `201` with `Location: /api/v1/orders/{id}`.
8. **Time and ids.** A `Clock` bean (`shared.config`) makes `createdAt` testable; the instant is cut to microseconds because PostgreSQL stores microseconds, so the `201` body equals the later `GET` body. The order id is generated by the application (`UUID.randomUUID()`).
9. **k6 scenario** `orders-create.js` posts an order of 1 + 2 coffees and checks status 201 and total 3320. It reads two coffee ids once, in `setup`, from `GET /api/v1/coffees`.
