# ADR: App assets extracted from the Figma file

- Status: Accepted and verified
- Date: 2026-11-05
- Spec: [.specs/014-app-assets-from-figma.md](../.specs/014-app-assets-from-figma.md)
- Plan: [plans/014-app-assets-from-figma-plan.md](../plans/014-app-assets-from-figma-plan.md)

## Context

The app must use the real logo, icons, coffee photos, hero image, and illustration of the design, and the project must build without the Figma file, which is large and stays on the developer's machine (spec 001). The Figma MCP has no access to the file (see the design analysis), so the assets are read from the local `.fig` export. The decoding of the analysis was done outside the repository, so it was rebuilt and committed here.

## Decisions

1. **No Figma library; a small decoder of our own** (`scripts/lib/fig-file.mjs`, about 240 lines). A `.fig` is a ZIP; `canvas.fig` is a `fig-kiwi` container with a Kiwi schema chunk and a document chunk (deflate or zstd, told apart by the zstd magic bytes); `images/<sha1>` are the PNGs. The ZIP and Kiwi readers use only `node:zlib`. This keeps the repository free of an unmaintained reverse-engineered package, and the decoder has its own tests built on bytes written in the test.
2. **Node 22.15 or newer for the script.** The document chunk is zstd, and `node:zlib` has zstd from 22.15. The script checks at run time and says so; the root `engines` stays `>=22.12` because the app and the tests do not need zstd. The one test that decodes the real file is skipped when the file is missing, and the zstd test falls back to deflate on an older Node.
3. **Photos are matched by hash, never by position.** The 14 cards of the Home screen are instances of the `Type=Catalog` symbol. The title is the text override (or the symbol default) and the photo is the symbol chosen for the nested `Coffee` instance (an override or the default); that symbol holds one rectangle with an image paint, and the paint hash names the file in `images/`. The Portuguese title maps to the slug (`FIGMA_COFFEE_NAMES`). Three cross-checks stop the script on any mismatch: the grid order of the cards (by position on the page) equals the seed order; the photo symbols of the Style Guide have the same hashes; each photo is square and at least 240 px. One mapping is not obvious and is why hashes are used: the card "Expresso Gelado" shows the symbol `Type=Café Gelado`, and the card "Mocaccino" shows `Type=Mochaccino`.
4. **Photos and the hero image are copied byte for byte.** No resize, no re-encoding. They are transparent PNGs of 320 to 1332 px (the hero is 1070 × 810, 2.25 times its 476 × 360 frame, with the yellow shape and the purple arc already in it). Weight: 14 photos 1778 kB (52 to 483 kB each, the macchiato being the largest) and the hero 504 kB, 2.2 MB in all. The catalog shows them at 120 × 120 and the cart at 64 × 64, so this is more than the screen needs; the spec says to optimize only when the report shows a problem, so it is recorded here and left for a later decision (see Consequences).
5. **Icons are the vector outlines of the Style Guide symbols, as SVG in `currentColor`.** A vector's `fillGeometry` is a binary path blob (0 close, 1 move, 2 line, 3 quadratic, 4 cubic, float32 coordinates in the node's own space) that is turned into SVG path data; the node transforms accumulate from the symbol down. Each icon is `viewBox="0 0 32 32"` with `fill="currentColor"` and no other color; the Figma names are normalized (`-regular` dropped, the `currenc-dollar` typo fixed). The script stops when the 13 are not exactly the 13 of the spec.
6. **The manifest exposes icons as SVG markup, not URLs** (`iconSvgs`), imported with Vite's `?raw`. Only an inline SVG can take the color of the text around it, which is what "colors itself with `currentColor`" needs. Logo, hero, and illustration are URLs, because they keep their own colors.
7. **Logo and illustration keep their colors.** The logo is one vector with two fills: the base fill (`Base/Subtitle`, `#403937`) and a style override that points to the `Brand/Purple` style (`#8047F8`); the script resolves the override to the color of that style. The illustration is the 96 solid-fill vectors of the Success frame with their transforms.
8. **One new library: `@napi-rs/canvas` 1.1.0** (root dev dependency, exact version, used by the script only, never bundled in the app). The contact sheet must decode PNGs, scale them, and draw text, which `node:zlib` cannot do. It ships a prebuilt binary and needs no system library. The `yarn.lock` also lists the prebuilt packages of the other platforms as optional entries.
9. **The manifest names every file** (`src/assets/index.ts`), so a missing file fails `tsc` and the build, never the browser. `COFFEE_SLUGS` and `ICON_NAMES` are `as const` lists with derived types (`CoffeeSlug`, `IconName`), and the lookups are `Record`s over them, so a slug without an image does not compile.
10. **Generated, deterministic, and documented.** Running the script twice on the same file gives identical bytes (checked by hashing every output). It also writes `docs/design/assets-mapping.md` (the Figma card, the photo symbol, and the hash of each slug) and `docs/design/coffee-images-contact-sheet.png`, both committed. The `.fig`, the PDF, and `image-frames.png` stay ignored.
11. **Tailwind no longer scans `src/assets`** (`@source not "../assets";` in `index.css`). The SVGs have attributes such as `transform="matrix(…)"`; Tailwind took the word `transform` for a class and added its utility and 5 `@property` rules to the CSS (+0.7 kB). The assets hold no class names. A root test pins the line. With it, the built CSS is byte for byte the CSS of the commit before this spec.

## Verification

- Six QA commands pass: 130 Vitest tests (96 before, 34 new for the assets: slugs, a file for each, square PNGs of at least 240 px, 13 icons in `currentColor`, sizes of logo, hero, and illustration), 96 root Node tests (82 before, 14 new: 12 on bytes built in the test, one on the real file, one that pins the Tailwind source rule), strict `tsc` including the manifest, the API suite unchanged, 5 Playwright tests (run on port 5174 because 5173 is in use on this machine), and `vite build`.
- With the `.fig` moved out of the checkout, `vite build`, the 130 Vitest tests, and the root tests pass (the real-file test is skipped), so the committed assets are enough to build.
- The contact sheet and a rendering of the icons, logo, hero, and illustration were looked at: each photo shows the drink its slug names, the icons are the 13 of the spec, the logo has its two colors, and the illustration is the delivery person on the purple scooter.
- The CSS size reported in the ADR and the plan of spec 013 (6.65 kB) could not be reproduced; the commit of spec 013 builds to 8.86 kB (2.25 kB gzip), and so does this one. Both documents are corrected.

## Consequences

- The 14 photos and the hero weigh 2.2 MB as they are. A page that shows the whole catalog fetches 1.8 MB of photos for thumbnails of 120 px. A later spec should resize them to the 2x display size (240 px) and re-encode (WebP or optimized PNG), which should cut the weight a lot (to be measured then); the script is the place to do it, so the result stays reproducible. This is not done here because the spec asks for byte-for-byte assets unless the report shows a problem, and the decision to change format belongs to the owner.
- A new coffee needs a card in Figma, an entry in `FIGMA_COFFEE_NAMES`, a slug in `COFFEE_SLUGS` (the script, the manifest, and the seed must agree: a root test compares the three), and a run of the script.
- The extractor knows the structure of this one file (the `Type=Catalog` symbol, the "Ícones" frame, the `Coffee Delivery - Home` and `- Success` screens). A restructured file makes it stop with a message that names what is missing, not write wrong assets.
- Components (spec 015 onward) render an icon by inlining `iconSvgs[name]` and coloring it with a text color token.
- New library: `@napi-rs/canvas` 1.1.0 (root dev dependency).
